# 설계 문서 형식

> 쓰는 규칙·자리 구분·검사는 전역 `design-doc` skill 을 따른다. 여기는 /prd 산출물의 파일·머리말·결정 절 형식만

## 파일

- 작업 폴더의 `NN-<주제>.md`. 번호는 02 부터 (00 understand, 01 verify)
- 독자와 수명이 다르면 문서를 나눈다
  - 설계 결정 — 승인 대상
  - 외부 연동 스펙 — 구현자가 PR 마다 참조
  - 로그·데이터 설계 — ETL·정산·대시보드가 참조
  - 클라이언트(SDK·앱) 설계 — repo 와 릴리스 주기가 다름

## 머리말

```markdown
# <설계 문서 제목>

|               |                                    |
| ------------- | ---------------------------------- |
| 이슈          | #<n>                               |
| 코드 기준     | <브랜치> `<sha>`                   |
| PRD 기준      | [<PRD 제목>](URL) <최종 수정 시각> |
| 다루는 PRD 절 | §5.2, §5.3                         |
| 짝 문서       | <같은 작업 폴더의 다른 설계 문서>  |
| 상태          | 초안 / 확정                        |

## 목차

<##/### 2단계>
```

## 본문

- 맨 앞 절은 전체 구조 그림 (diagram 단계 범례)
  - 🟩 새로 생기는 단계 · 🟨 입력·형태가 바뀌는 단계 · ⬜ 그대로인 단계
- 다음 절은 변경점 표: 컴포넌트 / 무엇이 바뀌나 / 근거 `file:line`
- 결정 하나 = 절 하나. 절 제목은 결론 문장 ("경매 엔진은 Go 로, TR 안에 둔다")
- 결정 절의 구성
  1. 결론 (1~2문장)
  2. 근거 — 현재 동작 `file:line`, 실측값, PRD 제약
  3. 기각한 대안과 이유
  4. 해당하면 표시
     - `PRD 와 다름:` PRD 권장·가정과 다른 결정과 그 이유
     - `기존 설계와 다름:` 참고한 기존 설계 문서와 다른 결론과 그 이유
     - `미결정 의존:` 이 결정이 기대는 미결정 항목 (D#)
- 실측 수치는 부록으로. 재현 명령을 함께 남긴다
