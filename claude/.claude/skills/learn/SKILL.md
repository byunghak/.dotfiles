# Learn

**작업이 끝난 뒤, 확정된 결과로 학습 노트를 쓴다.**

작업 도중 쓰는 노트는 아직 틀린 줄 모르는 가정을 가르친다. 세션이 끝난 뒤에 쓰면
"틀렸다가 정정된 것"까지 담을 수 있다.

```
/learn [세션 id | 생략=현재 세션] [주제]
   │
   ├─ ① 세션 기록 읽기     사용자 메시지 · 답변 · 도구 결과(쿼리·로그)
   ├─ ② 배울 점 뽑기       4종류
   ├─ ③ 초안 보이기        터미널 (ASCII 그림 + 표)
   └─ ④ 승인 후 덧붙이기   <출력 위치>/<챕터>.md 또는 용어집
```

## 메모리와의 차이

|      | 메모리 (`~/.claude/projects/.../memory/`) | learn              |
| ---- | ----------------------------------------- | ------------------ |
| 독자 | 다음 세션의 Claude                        | 사용자             |
| 내용 | 앞으로 어떻게 일할지                      | 무엇을 알게 됐는지 |

- 둘 다 해당하는 내용이면 learn 에만 쓰고, 메모리가 필요하면 따로 제안한다

## ① 세션 기록 읽기

- **세션 id 생략 + 현재 세션이 compaction 되지 않음** → 대화 맥락을 그대로 쓴다
- **세션 id 지정, 또는 현재 세션이 compaction 됨** → 스크립트로 추린다

```bash
~/.claude/skills/learn/scripts/transcript.sh <session-id | path.jsonl> [project-dir]
```

- `project-dir` 생략 시 현재 디렉토리 기준으로 `~/.claude/projects/<key>/` 를 찾는다
- 출력이 길면 `[주제]` 키워드로 grep 해 범위를 좁힌다
- 도구 결과는 1500자에서 잘린다. 핵심 수치가 잘렸으면 원본 jsonl 을 직접 본다

## ② 배울 점 뽑기

| 종류             | 무엇                                                           | 예시                                                         |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| 정정된 사실      | 처음 믿었다가 증거로 바뀐 것. **처음 가정과 정정 근거를 함께** | "청구는 3일 늦다" → 사용 후 12시간에 84% 도착                |
| 시스템 동작·개념 | 세션에서 확인한 동작 원리                                      | ConfigMap `envFrom` 반영 시점, PromQL `increase()` 리셋 보정 |
| 결정과 이유      | 고른 것 + **기각한 대안과 기각 이유**                          | 14일 중앙값 대신 상한 기준                                   |
| 써먹을 명령·함정 | 다시 쓸 명령, 밟았던 함정                                      | GMP 를 `kubectl get --raw` 로 조회, zsh 변수 단어 분리       |

- 근거는 도구 결과(쿼리 결과·로그·코드)에서 가져온다. 내 답변만 있고 도구 결과로 확인 안 된 주장은 뽑지 않거나 "미확인" 으로 표시한다
- 세션 안에서 정정된 주장은 **최종 버전만** 사실로 쓴다
- `[주제]` 가 있으면 그 주제에 걸린 것만 뽑는다
- 일반 상식(누구나 아는 git 명령 등)은 뺀다. 이번 세션에서 처음 확인한 것만

## ③ 초안 보이기 (터미널)

쓰는 규칙:

- 결론부터 짧게. 수식·`file:line` 을 먼저 던지지 않는다
- 추상 비유어(축·노브·경계·층) 대신 구체어
- 그림은 ASCII (터미널은 mermaid 를 렌더하지 않음)
- 낯선 용어는 처음 쓸 때 한 줄 정의
- 코드 근거는 `tracing-system-internals` skill 규칙을 따른다

구성:

1. 요약 2~3줄
2. 4종류별 항목 (없는 종류는 생략)
3. 각 항목의 **덧붙일 위치** — 어느 파일의 어느 절인지
4. 이미 문서에 있는 개념 → 새로 쓰지 않고 "링크만" 으로 표시

## ④ 승인 후 덧붙이기

### 출력 위치 결정

```
레포 루트에 docs/learning/ 있음?
   ├─ 예  → 그 안에서 챕터 고름
   └─ 아니오 → 사용자에게 위치를 묻는다 (기본 제안: docs/learning/)
```

- 챕터 고르기: `ls` 로 목차를 보고 주제가 맞는 챕터에 절로 덧붙인다
  - 맞는 챕터가 없으면 새 챕터 파일을 제안한다 (번호는 기존 규칙을 따름)
  - 용어 하나짜리는 용어집(`99-glossary.md` 등) 표에 행으로 추가
- 중복 확인: 덧붙이기 전 `grep` 으로 같은 개념이 이미 있는지 본다. 있으면 링크만
- 문서에는 mermaid 를 써도 된다 (뷰어가 렌더함). 터미널 초안의 ASCII 를 옮길 때 변환 여부는 기존 문서 스타일을 따른다
- 각 덧붙인 절 끝에 출처 한 줄: `> 출처: 세션 <id 앞 8자>, YYYY-MM-DD`

### 하지 않는 것

- 학습 문서를 커밋하지 않는다. git 추적 여부(`git status`)를 확인하고, 추적되는 파일이면 사용자에게 알린다
- 승인 전에 파일을 쓰지 않는다
