# paper-analysis

논문 한 편을 원문 기준으로 읽고, 수치는 표에서 그대로 옮기고, 우리 코드와의 비교는 코드로 확인한 것만 쓴다.

```
① 원문 받기 ×2 (독립) ──▶ ② 표 대조·산술 검산 ──▶ ③ 코드 대조 (file:line) ──▶ ④ 보고
```

research-review 와의 차이: 그쪽은 "결론이 설계를 좌우하는 조사" 에 조사 2개 + 비판 4개를 쓴다. 이쪽은 논문 한 편 요약이라 비판 단계 대신 표 대조·산술 검산으로 거른다. 논문 결론을 근거로 설계를 바꾸려 하면 그때 research-review 로 넘어간다.

## ① 원문 받기

- abs 페이지 + HTML 판(`arxiv.org/html/<id>v1`)을 읽는다. HTML 이 없으면 PDF. 초록만으로 판단하지 않는다
- `curl` 은 전역 hook(remote-command-guard)이 막는다. WebFetch 가 없으면 `web-fetch` agent 를 쓴다
- 같은 페이지를 **독립 agent 2개**로 받는다
  - 하나는 전체 보고(메타·문제·방법·실험·한계·도메인)
  - 다른 하나는 주요 표·핵심 문장(보상식·한계 문장·지연 주장 등)의 **원문 그대로**
  - 이유: agent 보고는 요약하다 수치·별표(유의성)를 바꿀 수 있다. 두 보고의 표가 일치할 때만 수치로 쓴다
- PDF 를 내려받으면 scratchpad 의 새 빈 디렉터리에 두고 읽기만 한다. 실행하지 않는다
- 페이지가 없거나 ID 가 틀리면 그대로 보고하고 멈춘다. 내용을 지어내지 않는다

## ② 표 대조·산술 검산

- 두 보고의 표를 셀 단위로 맞춘다. 다르면 어느 쪽이 맞는지 다시 받거나 "불일치" 로 적는다
- 표 사이 항등식을 검산한다 (예: 매출 = 요청 수 × RPM, fill rate = 응답 ÷ 요청). 맞지 않으면 "저자에게 물을 점" 으로 적고 오류로 단정하지 않는다
- 의심 설계 점검표:
  - 분산·신뢰구간·반복 수가 있는가
  - baseline 이 서론에서 비판한 기존 방법을 실제로 포함하는가
  - 헤드라인 수치의 구간(창)이 사후에 골라진 것인가, 전체 구간 값은 무엇인가
  - A/B 의 처리·대조가 예산·경쟁을 공유해 간섭(SUTVA)하는가
  - 하이퍼파라미터·데이터·코드 공개 여부
  - 측정하지 않은 지표로 결론을 내리는 문장

## ③ 코드 대조

- "우리는 X 를 한다/안 한다" 는 해당 경로 코드를 읽은 뒤에만 쓰고 `file:line` 을 붙인다
- 운영 동작 주장은 production values(helm 등) 플래그까지 본다. 못 봤으면 "확인 안 함"
- 적용 가능한 곳과 바로 쓰기 어려운 이유(규모·데이터·역할 차이)를 나란히 둔다

## ④ 보고 형식

1. 결론 2~3문장: 논문이 무엇이고 우리에게 쓸모가 있는지
2. 메타: 제목·저자·소속·날짜·venue
3. 문제 정의 / 방법(식 번호) / 실험(표 그대로, 제안 방법 표시) / 한계(저자 명시 vs 내 판단 구분)·재현성
4. 우리와의 관련성: 적용처·어려운 이유, 각 주장에 file:line 또는 "확인 안 함"
5. 확인 못 한 것·추정

검증 규칙:

- 수치는 두 독립 fetch 가 일치한 표에서만 옮긴다
- 저자 주장·내 판단·산술 검산 결과를 섞지 않고 표시한다
- 논문에 없는 값(β·K 등)은 "미보고" 로 적고 추정하지 않는다
