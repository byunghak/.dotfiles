# 읽기 검사

lint 는 형식만 본다. 문서를 처음 보는 에이전트에게 문서만 주고 질문해, 답이 맞는지와 답을 찾는 데 몇 절을 오갔는지 본다.

## 언제

- 큰 구조를 바꿨을 때 (뼈대·컴포넌트 틀 적용, 절 이동)
- 사용자가 "읽기 어렵다·길다" 고 했을 때
- 견본 절 하나만 고쳤다면 그 절에 대한 질문 1~2개만

## 순서

1. 질문 5개와 정답을 먼저 적는다 (scratchpad)
   - 독자가 실제로 찾을 것: 실패하면 무엇이 되나, 누가 언제 보내나, 왜 이렇게 했나, 끄는 법, 라이브 전 받아야 할 답
   - 정답에는 근거 절을 적는다
2. 에이전트 하나에 문서 경로만 주고 묻는다 — 대화 맥락을 주지 않는다 (fork 금지)

   ```
   아래 문서만 읽고 질문에 답하라. 문서 밖 지식·코드는 쓰지 않는다.
   답마다: 답 / 근거로 읽은 절 제목들 / 확신 (높음·낮음) / 헷갈린 점
   문서: <경로>
   질문: 1. … 5. …
   ```

3. 채점해서 표로 보고한다

   | 질문 | 정답 여부 | 읽은 절 수 | 헷갈린 점 |
   | ---- | --------- | ---------- | --------- |

4. 틀렸거나, 3절 넘게 오갔거나, 헷갈린 점이 있으면 그 절을 고친다
   - 답이 여러 절에 흩어짐 → 한 사실은 한 곳에
   - 답이 결정과 이유 토글 안에만 있음 → 결론 한 줄을 토글 밖으로
   - 용어를 몰랐음 → 처음 쓰는 곳에 한 줄 정의

## 보고

- 위 표와 고친 절만. "읽기 좋아졌다" 같은 평가는 하지 않는다
