# Edit Mode Rewriting Rules

> **우선순위**: 필체 프로파일(style-profile.md) > 프로젝트 스타일(write-style.md) > 아래 기본 원칙.
> 프로파일이나 프로젝트 스타일에 기록된 규칙이 기본 원칙과 충돌하면 프로파일/프로젝트 규칙을 따른다.

## 한국어 기본 원칙

- **결론을 먼저** — 독자가 계속 읽을지 판단할 수 있도록
- **구체적인 예시 > 추상적 설명**
- 기술 용어는 **정확하게**, 불필요한 풀어쓰기 금지
- "왜 이게 중요한가"를 **독자 관점에서** 명확히
- 불필요한 겸손 표현 제거 ("~해보려고 합니다" → "~합니다")

## 영어 기본 원칙

- **Active voice 우선** ("was implemented" → "we implemented")
- **Filler 제거** ("In order to" → "To", "It is important to note that" → 삭제)
- 기술 용어는 **첫 등장 시 약어 병기** 후 이후 약어만 사용
- **한 문장 = 한 아이디어**. 접속사로 3절 이상 연결 금지
- **Hedging 최소화** ("might perhaps" → "can", "I think maybe" → 삭제 또는 단정)

## 플랫폼별 특화

### 링크드인

- **첫 2줄이 훅** 역할 (더보기 클릭 유도)
- **스캔 가능한 구조** (짧은 단락, 공백 활용)
- **구체적인 숫자/결과** 포함

### 블로그

- SEO를 의식한 **소제목 구조**
- 코드 예시는 **실제 동작하는 최소 형태**로
- 독자가 가져갈 **1가지 핵심 takeaway** 명확히

### 기타 (노트, 에세이)

- 플랫폼 규칙 없음 — 필체 프로파일 + 프로젝트 스타일만 참조
