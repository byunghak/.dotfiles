## 문서 계층

| 문서 | 담는 것 | 독자 |
| --- | --- | --- |
| 설계 문서 (요약) | 목표, 흐름 그림, 컴포넌트마다 바뀌는 것·핵심 규칙·결정 1줄, 질문, WBS | 팀 전체 |
| WBS 항목 토글 (설계 문서 §WBS, 임시) | 이슈가 아직 없는 항목의 명세 — 필드·컬럼 목록, 코드표, 예시, 구현 주의점 | 구현자 |
| GitHub 이슈 | 이슈가 있는 항목의 명세. 이슈를 만들면 WBS 토글에서 옮기고 토글을 지운다 | 구현자 |
| decision-log | 왜·비교한 안·근거 분석·경위 | 나중에 이유를 찾는 사람 |

- 한 명세는 WBS 토글과 이슈 중 한 곳에만 둔다. 본문(목표·흐름·컴포넌트)에는 값·필드 목록을 쓰지 않는다
- 컴포넌트마다 맨 위에 명세가 있는 곳을 한 줄로: `명세: #1293` · `명세: [WBS](#3-wbs) #20`
- 결정이 바뀌면: 설계 문서 1줄 · decision-log 경위 · 명세가 있는 한 곳

## 머리말·목표

```markdown
# <제목>

- 상태: 초안 / 확정 · 상위 이슈 #N
- 기준 리비전: <repo> <branch> `<sha>`
- 영향 범위: <컴포넌트 나열>

## 목차

## 0. 목표

- <무엇을 하는 프로젝트인가 한 줄>
- 범위: <파일럿·플랫폼·대상>
- 성공 기준: <PRD KPI 그대로>
```

- 목표는 3~5줄. "TR 이 … 하고, 사이드카가 …" 같은 구조 설명은 흐름 절 몫이다
- 목차는 `##`·`###` 두 단계. 절을 바꾸면 목차도 같이

## 흐름

- API·시나리오마다 `###` 하나: 요청·응답 예시 토글 → 시퀀스 그림 → 그림만으로 안 보이는 순서 2~3 bullet
- 규칙·값·예외는 쓰지 않는다. 그 컴포넌트의 `동작` 에 둔다
- 전체 구조 그림은 `### 1.1` 에. 🟩 새로 · 🟨 바뀜 · ⬜ 그대로

## 컴포넌트

```markdown
### 2.N <컴포넌트 이름>

명세: #N · 상세 — <절>

#### 바뀌는 것

- 🟩 <새로 생기는 것>
- 🟨 <바뀌는 것>

#### 동작

<그림>

<표>

<!-- -->

- <규칙>: <설명>

#### 결정과 이유

```markdown
- 외부 DSP 호출은 Rust 사이드카에 둔다 — TR 메인 Go 힙을 늘리지 않기 위해
- 외부 tracking 은 폴더를 나눈다 — 같은 경로 + 필터는 누락 때 정산이 멈춘다

  | 안                 | 판정 |
  | ------------------ | ---- |
  | 같은 경로 + 필터   | 기각 |
  | **폴더 분리**      | 채택 |
```

- 결정 하나 = 1줄: "결론 — 한 줄 이유"
- 표는 꼭 필요할 때만, 3행 이하, 칸은 짧게. 기준별 비교·근거 분석·리스크·대가는 decision-log
- 토글로 근거를 접지 않는다 — 접을 만큼 길면 decision-log 몫이다
- 날짜·"재결정"·"10-04 안을 바꿈" 은 쓰지 않는다
- `PRD 와 다름:` 은 해당할 때만 한 줄

## 질문

```markdown
## 4. 결정·고민 사항

### 4.1 고민 사항   ← 기본안이 없거나 팀 논의가 필요
### 4.2 결정 사항   ← 기본안으로 진행, 다르면 알려 달라 (주제별로 정렬)
### 4.3 확인 사항   ← 외부 답 대기
```

- 묻는 상대가 아니라 항목의 상태로 `###` 을 나눈다. 번호는 `고민 N`·`결정 N`·`확인 N`
  - 누가 정하는지는 토글 안 "정할 사람" (확인은 "답할 곳") 한 줄
- 한 항목 = 토글 하나: 질문·배경·기본안·정할 사람
- "답 없이는 라이브 불가" 같은 단정 대신 제목에 "(라이브 전 필요)"
- 본문의 "가정 — PO 확인 중", "Moloco 에 물을 것" 은 모두 여기로. 컴포넌트 `미정` 에는 "결정 — floor 기준" 처럼 분류와 주제만
- 정해지면 행을 지우고 본문에 반영한다. 경위는 decision-log

## 문장

- bullet 우선. 한 bullet 은 한 가지. `<어떤 일>: 설명`
- 한 줄 90자 이내 (표·코드 제외). 3줄 넘는 문단은 bullet 으로
- 결론만 남긴다. "~가 핵심이다", "~것이 중요하다", 같은 사실의 재진술 금지
- 추상 비유어 금지 — 축·노브·경계·층·조각·흡수·받친다 (영문 axis·knob·layer 도)

  | 쓰지 않음           | 대신                                |
  | ------------------- | ----------------------------------- |
  | 두 값을 같은 축으로 | 두 값을 같은 기준으로 비교 가능하게 |
  | MARGIN 은 실험 노브 | MARGIN 은 실험이 바꾸는 설정값      |
  | 어댑터 경계 한 곳   | 어댑터에서 변환하는 한 곳           |
  | 행을 `dsp_id` 로 가른다 | 행을 `dsp_id` 로 분류한다 |

- PRD 내부 약칭(Tier 0 등)은 풀어 쓴다. 낯선 용어는 처음 쓸 때 한 줄 정의
- "리더십 승인" 대신 "결정 필요"
- PRD 요구를 먼저, 덧붙인 설계는 뒤에. 덧붙인 것은 `PRD 요구 아님` 표시

## 그림·표

- 절 안 순서: 그림 → 표 → 문장 bullet
- 표·그림은 소속 bullet 아래 들여쓰기. 그 뒤 문장 bullet 목록 앞에 빈 줄 + `<!-- -->` + 빈 줄
- 굵은 제목 줄(`**흐름**`)로 bullet 을 대신하지 않는다
- 다이어그램은 mermaid. 라벨은 한글, 식별자는 영문. 대화 응답에서는 ASCII
- 표의 칸이 길면 칸을 늘리지 말고 표 아래 bullet 으로

## 토글

토글은 WBS 절의 항목 상세와 질문 절에만 둔다. 본문(목표·흐름·컴포넌트)에는 두지 않는다.

- 단계 표 아래에 항목마다 토글 하나: `<summary>#20 외부 DSP 사이드카 계약</summary>`
- 질문은 표 대신 질문마다 토글 하나: 제목 = 번호·질문·(막힘), 안 = 질문 · 배경 · 기본안 3줄
- 토글 안에 `###` 제목을 두지 않는다 — Notion 변환에서 제목이 토글 밖으로 빠진다
- 들여쓴 `<details>` 는 Notion 변환에서 안의 목록이 한 문단으로 뭉개진다 (lint 오류)
- 근거를 토글로 접지 않는다 — 근거는 decision-log
- 문서 길이 상한(500줄)은 토글 안을 빼고 센다

## 링크·번호

- 다른 문서는 파일명 대신 제목 링크: `[참고 — TR 요청·응답](ref-tr-request-response.md)`
- 길 안내 문장 금지 — "용어는 맨 아래", "자세한 건 아래 절"
- 내가 만든 번호(A6, E3)를 쓰지 않는다. PRD 번호(D11)·WBS `#`·GitHub `#N`·질문 절 `#` 만
- 결정을 절 번호로만 가리키지 않는다. 내용으로, 번호는 괄호로
- 한 bullet 을 여러 줄로 이어 쓰지 않는다 (들여쓴 이어지는 줄) — Notion 가져오기에서 목록이 깨진다. 긴 인용은 표로
- 질문도 번호만 쓰지 않는다. `(차감액 미정 — 엔지니어 1)` 처럼 주제 먼저, 번호는 괄호로. 주제는 질문 토글 제목에서 줄인다
  - 예외: WBS 표 "막는 질문" 열은 번호만

## 넣지 않는 것

- 결정 날짜, 결정 경위, 정정 기록 → decision-log (사건·측정 날짜는 근거로 쓴다)
- 구현 위치 → WBS (결정 근거 `file:line` 은 `결정과 이유` 에)
- ROAS 같이 계속 바뀌는 성과 수치. 설계 근거 수치(지연 예산 등)는 둔다
- 승인 안 된 결정, 리뷰 도구·에이전트 이름

## 목차 앵커

GFM 규칙: 소문자 → 단어문자·공백·하이픈·`_` 만 남김 → 공백을 **개수 그대로** `-` 로.

- `—`·`·`·`` ` ``·`/`·`{}` 은 지워지고 양옆 공백은 남는다
  - `1.2 init — /v1/tr/init` → `#12-init--v1trinit`
- doc_lint.py 가 깨진 링크를 잡는다

## 그림 아래 문장

그림을 넣었으면 그 아래 bullet 은 그림으로 안 보이는 것만 둔다.

- 그림이나 WBS 명세에 이미 있는 내용을 bullet 로 다시 쓰지 않는다
- "…은 2.9", "…는 WBS #1 대응표" 처럼 절 번호만 가리키는 줄은 두지 않는다 (참조는 문장 끝 괄호로)
- 실패·예외 흐름(타임아웃, 대기 상한, 폴백)은 그림 안에 넣는다 — 시퀀스는 `opt`/`alt`, 흐름도는 분기 화살표
- 그림 Note 안에 절 번호를 쓰지 않는다 — 단계 번호와 섞인다

## 바뀌는 것과 장점

- 지금 구조에도 있는 것을 "바뀌는 것"·"장점" 으로 쓰지 않는다 — 지금 구조를 코드·운영 답변으로 확인하고 쓴다
- 다른 안도 똑같이 갖는 대가는 비교 표에 넣지 않는다
- 정하지 않은 값(질문 절에 있는 것)은 본문에서 "기본안" 이나 "미정 — 주제 (질문 번호)" 로만 쓴다
