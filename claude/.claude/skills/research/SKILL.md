# research

조사 갈래를 고르고 그 reference 만 읽는다. 모든 갈래는 보고 전에 아래 check loop 와 독립 검증을 통과한다.

```
요청 ─▶ 갈래 고르기 ─▶ reference 읽고 조사 ─▶ check loop ─┬─ 통과 ─▶ 독립 검증 ─▶ 보고
                                                ▲            │
                                                └─ 다시 조사 ◀┘ (빠진 항목만, 최대 2회)
```

## 갈래

| 요청                                                         | 읽을 reference                  |
| ------------------------------------------------------------ | ------------------------------- |
| 코드 동작·호출 경로·설정 출처 파악, 문서 축적                | `references/code.md`            |
| 운영 데이터로 원인·수치 확정                                 | `references/production-data.md` |
| 논문 한 편 분석                                              | `references/paper.md`           |
| 도구·방식·대안 비교 (결론이 설계를 좌우하지 않음)            | `references/compare.md`         |
| 결론이 설계·계약·외부 약속을 좌우함, 사용자가 대조·비판 요청 | `references/review.md`          |

- 한 요청이 두 갈래에 걸치면 둘 다 읽는다 (예: 운영 수치 + 그 값을 만드는 코드 → production-data + code)
- 비교 조사의 결론으로 설계를 바꾸게 되면 그때 review 로 올린다

## check loop (모든 갈래, 보고 전)

보고 초안을 아래 표로 확인한다. 하나라도 걸리면 보고하지 않고 그 항목만 다시 조사한다.

| 확인                                                                               | 걸리면                                          |
| ---------------------------------------------------------------------------------- | ----------------------------------------------- |
| 사용자 질문 원문의 물음마다 답이 있나                                              | 빠진 물음만 다시 조사                           |
| 결론·권고 1순위를 바꾸는 주장을 main 이 원본(코드 줄·문서 문장·쿼리)에서 직접 봤나 | 직접 본다. subagent 보고를 그대로 옮기지 않는다 |
| 두 조사(또는 조사와 내 이해)가 어긋나는 주장이 있나                                | 원본을 열어 가른다                              |
| "추정·미확인" 중 조회 한 번(검색·파일 한 줄·쿼리)으로 닫히는 것이 있나             | 지금 닫는다                                     |

- subagent 에 다시 맡길 때는 SendMessage 로 그 항목만 보낸다. 새 agent 를 띄우지 않는다 (앞서 읽은 원본을 다시 읽지 않게)
- 2회 돌아도 안 닫히면 보고의 "확인 못 한 것" 에 닫지 못한 이유(권한·원본 없음·사람에게 물어야 함·문서 잘림)와 함께 적는다. "시간이 없어서" 는 이유가 아니다
- 보고 맨 아래에 한 줄: `check: 질문 N/N 답함 · 핵심 주장 M개 원본 확인 · 미확인 K개 · 독립 검증 틀림 X·미확인 Y`

## 독립 검증 (check loop 통과 뒤, 보고 전)

조사한 문맥 없이 핵심 주장만 다시 확인해, 조사 중 굳어진 해석이 결론으로 넘어가지 않게 한다.

1. 결론·권고를 받치는 핵심 주장을 최대 8개, 한 줄씩 적고 주장마다 근거 위치(파일:줄·URL·쿼리)를 붙인다
2. 새 Agent 하나(`model: "sonnet"`, `effort: "high"`)에 이 목록만 넘긴다. 조사 과정·결론·권고는 넘기지 않는다
   - prompt: "주장마다 근거 위치의 원본을 직접 열어 `확인 / 틀림 / 미확인` 과 근거 한 줄. 15줄 이내, 원본 출력 붙이지 말 것"
3. 결과 처리

   | 판정   | 처리                                                                                      |
   | ------ | ----------------------------------------------------------------------------------------- |
   | 틀림   | main 이 원본을 직접 열어 가린다 (검증 agent 도 틀릴 수 있다). 결론이 바뀌면 check loop 로 |
   | 미확인 | 보고의 "확인 못 한 것" 에 이유와 함께 적는다                                              |

- 핵심 주장이 1개 이하인 조사는 건너뛰고 check 줄에 `독립 검증 생략` 으로 적는다

## 공통 보고 형태

- 결론 2~3문장 먼저. 불확실하면 거기서 밝힌다
- 확인된 사실 / 추정 / 권고를 섞지 않는다. 추정에는 "추정" 을 붙인다
- 결정이 필요한 것은 보고와 분리해 AskUserQuestion 으로
