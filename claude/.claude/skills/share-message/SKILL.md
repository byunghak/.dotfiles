# 공유용 내용 (엔조 화법 + 사실 검토)

엔조 이름으로 동료에게 공유할 내용을 엔조의 말투로 쓰고, 그 안의 기술 주장을 보내기 전에 코드로 대조한다. 엔조는 SDK·광고 영역을 배우면서 답하는 중이라, 메모에 적힌 주장도 틀릴 수 있다.

## 1. 상대 글 쪼개기

상대 글의 bullet·질문을 하나씩 나열한다. 엔조 메모에 없는 항목도 빠뜨리지 않고 답변 한 줄을 배정한다. 확신이 없으면 "이렇게 이해했는데 맞을까요?" 로 받는다.

초안에 넣는 요청·약속은 엔조 메모나 상대 글에서 나온 것만이다. 새로 떠오른 요청은 초안 밖에 "추가 제안" 으로 따로 적는다.

## 2. 주장 대조표 (필수)

초안에 들어갈 기술 주장(메모의 것 + 상대 글의 것)을 전부 표로 만들고, 행마다 코드·문서로 확인한다.

| 주장 | 출처(엔조/상대) | 확인 결과 | 근거 `file:line` |
|---|---|---|---|
| … | … | 맞음 / 틀림 / 반만 맞음 / 미확인 | … |

- 미확인 행은 초안에서 단정하지 않는다 ("~로 보이는데", "검토는 해보겠습니다").
- 틀린 행은 초안에 사실대로 고쳐 넣고, 엔조에게 무엇이 왜 바뀌었는지 보인다.
- 수치(크기·ms·초)는 하나도 빼지 않고 대조한다.
- "누가 정하는가(SDK/서버/앱)" 류 주장은 값을 **정하는 곳**과 **강제하는 곳**을 나눠 확인한다.
- 한 주장에 대상이 여럿이면(예: "타이머와 노출이 멈춰야") 대상마다 따로 확인한다. 하나만 확인하고 행을 닫지 않는다.
- 설정값은 그 값을 같이 쓰는 다른 곳(다른 광고 포맷 등)이 있는지 함께 확인한다.

## 3. 엔조 화법

- 첫 줄: `@상대 님` + 짧은 인사 (늦었으면 "답변이 좀 늦었습니다. :pray:")
- 주제별 소제목은 굵게·기호 없이 평문 한 줄 (`갱신 주기 1안 확정`, `Adaptive 영역`). 그 아래 문장마다 줄바꿈.
- 어미: "~것 같네요", "~해야할 것 같아요!", "~하면 어떨까 싶습니다", "~해보겠습니다"
- 상대 의도 확인: "~하고 싶다는 것으로 이해했는데 요건 한번 더 설명 들을 수 있을까요?"
- 맡을 일: "작업 범위에 추가해두겠습니다" / "마찬가지로 작업 범위에 추가해둘게요"
- 결정이 어려운 건: "월요일 1on1 때 구두로 얘기해보면 좋을 것 같습니다!"
- 더 생각할 항목 끝에 `:brain:`
- 쓰지 않는 것: 인용 블록(`>`), 굵은 소제목, "—" 대시, "정리 감사합니다" 같은 형식적 인사, 마크다운 표

## 4. 출력 형식

초안을 새로 쓸 때:
1. 주장 대조표
2. 초안 전문 (코드 블록, 그대로 붙여넣을 수 있게)

엔조 초안을 검토할 때:
1. 결론 1~2문장: 사실과 다른 곳 N곳, 다르게 읽힐 곳 M곳
2. `## 틀린 부분` / `## 다르게 읽힐 수 있는 부분` — 표 `원문 | 문제 | 수정안`
3. "첨삭안" 요청 시: 수정 반영 전문(코드 블록) + 표 `원문 | 첨삭 | 이유`
4. 재검토 시: 앞서 짚은 곳 중 반영된 것 / 남은 것만

품질 판정("좋아요", "괜찮아요")은 붙이지 않는다. 바뀐 곳과 사실 일치 여부만 말한다.
