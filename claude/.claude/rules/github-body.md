# GitHub 본문 (이슈·PR 공통)

## 쓰기

- 본문·코멘트는 짧게: 결론 3줄로 열고, 근거는 판정에 필요한 최소량만 낸다
- 같은 로그·수치를 두 번 인용하지 않고, 함수 전체 대신 문제의 한 줄만 인용한다
- 결론에 영향 없는 배경·역사는 묻거든 낸다. 다음 작업 제안은 조사 결과와 같은 글에 섞지 않고 분리한다

## 본문 고치기 (올린 뒤)

- 고칠 때는 지금 상태로 다시 쓴다. 옛 내용을 취소선(`~~`)·"11-18 갱신" 같은 날짜 머리 인용 블록·"→ 옮김" 덧붙임으로 남기지 않는다. 바뀐 경위는 코멘트·커밋에 둔다
- 끝난 일은 표 한 줄(`할 일 | 상태 | PR`)로 줄이고, 진행 중·남은 일만 체크박스로 펼친다
- 계획이 바뀌면 새 계획을 본문에 쓴다. 코멘트나 다른 PR 에만 두지 않는다
- 이제 관계없어진 관련 링크는 지운다
- `gh issue edit`·`gh pr edit` 전에 `grep -nE '~~|^> .*갱신' <본문 파일>` 0 건 (11-18 사용자: #5027 해야 할 것이 취소선·갱신 블록으로 읽을 수 없었음)
