# verify 규칙

목적: PRD 가 코드에 대해 말하는 것이 **지금도** 맞는지 확인한다. PRD 는 작성 시점의 코드를 기준으로 쓰였고, 코드는 그 뒤에도 움직인다.

## 주장 추출

다음을 주장으로 본다:

- 경로·패키지·모듈 인용 (`services/x`, `sidecars/y/src/z`)
- 심볼·필드·엔드포인트 인용 (`TrRequest`, `revenueMicroUsd`, `POST /v1/tr/ilrd`)
- 상태 단정: "없다", "이미 구현", "부분", "전용", "N개 필드", "확장 슬롯 없음"
- 동작 단정: "X 는 Y 를 한다", "X 는 Z 방향뿐"
- 수치: 기본값·타임아웃·상수 (`기본 500ms`, `600초`)

주장이 아닌 것: 비즈니스 의도, 미래 계획, 외부 파트너 동작(우리 코드로 확인 불가 → "확인 불가")

## 판정

| 판정      | 뜻                                     | 근거                                                  |
| --------- | -------------------------------------- | ----------------------------------------------------- |
| 맞음      | 지금 코드와 일치                       | `file:line`                                           |
| 낡음      | 작성 당시엔 맞았을 수 있으나 지금 다름 | `file:line` + 바꾼 커밋 (`git log -S` / `git log -L`) |
| 틀림      | 작성 당시에도 근거를 찾을 수 없음      | 찾아본 위치                                           |
| 확인 불가 | 우리 코드 밖이거나 실측이 필요         | 무엇이 있어야 확인되는지                              |

- "없다" 주장은 grep 한 번으로 판정하지 않는다. 타입명·필드명·wrapper 이름으로 다시 찾는다
- 설정 기본값은 코드 기본값과 배포 설정(차트·매니페스트) 값을 각각 확인한다

## 01-verify.md

```markdown
# <PRD 제목> — 코드 대조

기준: <브랜치> `<sha>` · PRD 최종 수정 <시각>

요약: 맞음 N · 낡음 N · 틀림 N · 확인 불가 N

## 낡음·틀림 (설계 전제 교정 대상)

| PRD 절 | PRD 주장 (요약) | 판정 | 현재 코드 | 근거 |

## 확인 불가

| PRD 절 | PRD 주장 (요약) | 확인하려면 |

## 맞음

| PRD 절 | PRD 주장 (요약) | 근거 |
```

## 병렬 조사

- 주장이 10개를 넘으면 영역(서비스·언어·인프라)별로 Explore agent 에 나눈다
- agent 프롬프트에: 주장 원문, 판정 기준 표, `file:line` 필수, 불확실은 명시
- 결과를 합칠 때 같은 주장에 다른 판정이 나오면 직접 확인한다
