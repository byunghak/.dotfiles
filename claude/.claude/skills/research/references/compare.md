# 도구·방식·대안 비교

"대체할 만한 게 있나" 처럼 후보를 넓게 찾아 비교하는 조사. 결론이 설계·계약을 좌우하면 `review.md` 를 쓴다.

```
① main: 비교 기준·질문 목록 ──▶ ② 영역별 조사 ×2 (병렬, 안 겹치게) ──▶ ③ main 종합 ──▶ check loop
```

## ① 비교 기준 (main)

- 사용자의 지금 방식과 겪는 문제를 번호 없는 목록으로 적는다. 후보는 이 목록에 대어 비교한다
- 사용자 질문 원문을 그대로 남긴다 (check loop 의 첫 줄이 이것으로 확인한다)

## ② 영역별 조사

- 겹치지 않게 나눈다 (예: 공식 기능 / 외부 도구). 같은 범위를 둘이 하면 review 갈래다
- Agent subagent 2개를 한 메시지에서 background 로 (model 지정 없이 sonnet)
- 지시서에 넣는 것
  - 비교 기준 목록과 사용자 질문 원문
  - 원본을 직접 읽을 것 (공식 문서 WebFetch, GitHub README, `gh api repos/<o>/<r>` 로 스타·마지막 push). 기억으로 답하지 않는다
  - 성숙도: GA / beta / research preview / 실험, 방치·종료 여부
  - 후보마다 출처 URL, 확인 못 한 것은 "추정"·"미확인"
  - 문서가 잘려 못 읽은 부분은 어디까지 읽었는지

## ③ 종합 (main)

- 두 보고를 기준 목록 순서로 합친 표 하나: 후보 × 기준
- 어긋나는 주장, 결론 순위를 바꾸는 주장은 check loop 에서 원본으로 가른다
- "대체할 것 없음" 도 결론이다. 일부 차용할 아이디어는 결론과 따로 목록으로
