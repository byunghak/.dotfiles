# WBS 형식

## 단위

- 항목 1개 = GitHub 이슈 1개 = 독립적으로 설계·검증할 수 있는 기능 하나
- PR 로 쪼개지 않는다. PR 분리는 구현 skill(예: `/work`)의 몫
- 항목이 한 설계 문서 절보다 크면 나누고, 여러 절에 걸쳐 작으면 묶는다

## 공수 요인 (항목마다 표시, 숫자는 사용자가 정함)

| 요인        | 값 예시                                                       |
| ----------- | ------------------------------------------------------------- |
| 성격        | 신규 / 확장 / 설정만                                          |
| 걸친 repo   | 서버 1 / 서버 + SDK                                           |
| 묶인 미결정 | D2, D6 — 결정 전 착수 시 재작업 위험                          |
| 외부 의존   | 파트너 온보딩, 인증 절차, 리더십 승인                         |
| 선행 검증   | 실측이 필요한 가정 (예: 외부 API 가 값을 주는가)              |
| 검증 수단   | 기존 테스트로 가능 / 새 테스트 인프라 필요 / 운영 실측만 가능 |

## wbs.md

```markdown
# <PRD 제목> — WBS

공수 단위: <사용자가 정한 단위> · 상위 이슈: #<n>

| 항목 (이슈 제목이 될 한 문장) | PRD 절 | 설계 문서 절 | 선행 항목        | repo   | 요인      | 공수 | 상태                    |
| ----------------------------- | ------ | ------------ | ---------------- | ------ | --------- | ---- | ----------------------- |
| <한 문장>                     | §5.2   | 02§3         | <선행 항목 제목> | server | 신규 · D2 | <값> | 초안 / 생성됨 #n / 보류 |

- 항목은 제목으로 구분한다. W1 같은 임의 번호를 붙이지 않는다. 이슈가 생성되면 GitHub 번호 #n 을 쓴다

## 의존 그래프

<mermaid flowchart. 노드 라벨 = 항목 제목 요약 (mermaid 노드 id 는 내부용, 화면에 노출 안 됨)>

## 보류 사유

- <항목 제목> — <사용자가 말한 사유>
```

## 이슈 본문 템플릿

```markdown
## 요약

<항목이 만드는 것 2~3문장>

## 설계

- <설계 문서 절 링크 — Notion 게시본이 있으면 그것, 없으면 repo 경로>

## 선행

- #<n> <제목>

## 완료 조건

- <관측 가능한 기준: 테스트·게이트·지표>

## 묶인 미결정

- D# <항목> — <결정 전 착수 시 위험>
```

- 제목: `<이슈 제목 관례가 있으면 따름>`. repo 최근 이슈 제목 5개를 보고 맞춘다
- 하드랩 금지, 평범한 어투
- 라벨은 상위 이슈의 라벨을 기본으로 제안
