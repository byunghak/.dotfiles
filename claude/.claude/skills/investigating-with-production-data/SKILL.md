# Investigating With Production Data

## Overview

**결론은 원천 수치로 낸다. 조회 한 번으로 닫히는 미확인을 남긴 채 보고하지 않는다.**

프로젝트에 `.claude/references/production-data-sources.md` 가 있으면 먼저 읽는다 (버킷·메트릭·접근 경로).

## 보고 전: 미확인 닫기

보고 초안의 "미확인·추정·다음 단계" 항목마다 판정한다:

| 판정                                                      | 할 일                                        |
| --------------------------------------------------------- | -------------------------------------------- |
| 조회 한 번(쿼리·`kubectl get`·파일 한 줄 읽기)으로 닫힌다 | **지금 닫고** 결과를 근거 표에 넣는다        |
| 못 닫는다 (권한 없음, 원천 없음, 사람에게 물어야 함)      | "확인 안 한 것" 에 **닫지 못한 이유**와 함께 |

닫지 못한 이유는 권한·원천·사람 셋 중 하나다. "아직 안 돌림"·"이번엔 실행 못 함" 은 이유가 아니다 — 그 항목은 보고가 아니라 조회 목록에 있다. 지금 실행할 수 없으면 보고 대신 "보내기 전 돌릴 조회" 목록을 낸다.

시간 압박은 예외가 아니다. 조회 한 번은 회의에서 "모릅니다" 를 말하는 것보다 짧다.

| 합리화                                 | 실제                                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| "회의 전이라 원인만 빨리"              | 미확인이 남은 원인은 원인이 아니라 가설이다                         |
| "다음 단계로 적어 두면 된다"           | 읽는 사람은 그 조회를 직접 못 돌린다. 지금 돌릴 수 있는 사람은 나다 |
| "주된 원인은 확정됐고 나머진 부차적"   | 시간대·범위(리전·서비스 섞임)가 틀리면 주된 원인의 수치가 바뀐다    |
| "대부분 설명되니 충분"                 | 남은 차이 1건도 수치로 적고, 닫을 수 있으면 닫는다                  |
| "닫을 수 있다고 표에 적어 뒀으니 됐다" | 닫을 수 있다고 쓴 항목이 보고에 남아 있으면 규칙 위반이다           |

**Red flags — 보고를 멈추고 조회부터:** "확인 못 함" 옆에 이유가 없다 · "~로 추정" 인데 그걸 가르는 컬럼이 원천에 있다 · 시간대(UTC/KST)·필터 범위를 안 맞추고 수치를 비교했다.

## 원천 읽기: 내려받지 않는다

- 원천 parquet 는 `gcloud storage cp`·`aws s3 cp` 로 받지 않는다. DuckDB httpfs 로 **필요한 컬럼만 직접** 읽는다 (cp 실측 5분에 100MB, 직접 읽기는 456개 파일 집계 8초)
- GCS: `https://storage.googleapis.com/<bucket>/<path>` + `CREATE SECRET (TYPE http, BEARER_TOKEN '<access token>')`. 실행 예제·glob 처리는 `gcs_duckdb.py`
- 403 이면 토큰을 바꿔 다시: 사용자 토큰 → `gcloud auth application-default print-access-token`
- Prometheus 이력은 `query_range`. 반환 시각은 UTC — 차트·요청자의 시각대와 맞춘 뒤 비교한다

## 비율 비교

**두 비율을 비교하면 분모가 같은지 먼저 적는다.** 다르면 같은 분모로 다시 계산한 뒤 비교한다 (예: "어제 하루 전환 중 A 채널 비중 30%" 와 "오늘 오전 전환 감소율 50%" 는 기간·분모가 달라 비교 불가 → 둘 다 같은 시간 단위의 전환 수로).

이 규칙은 결론·요약 문단에도 적용된다. 다시 계산하기 전에는 결론에 두 비율을 나란히 쓰지 않고, 그 자리를 `[같은 분모로 재계산 후 기입]` 으로 둔다. 다른 절에 "분모 주의" 를 적었다고 결론의 비교가 허용되지 않는다.

## 보고 형태

보고는 이 세 부분으로 끝난다:

1. **결론** 2~3문장 — 원인과 기여량(수치). 불확실하면 여기서 밝힌다
2. **근거 표** — 주장 · 수치 · 원천(경로/쿼리/메트릭) · 시간대
3. **확인 안 한 것** — 항목 · 닫지 못한 이유(권한·원천·사람) · 결론에 미치는 영향

조회를 아직 못 돌린 채 초안을 쓰면: 닫힐 항목은 근거 표의 `[조회 후 기입]` 칸으로 두고, "보내기 전 돌릴 조회" 목록을 초안 앞에 붙인다. "확인 안 한 것" 칸에는 넣지 않는다.
