## 문장 구조

- 평균 문장 길이: 짧음 (5회 관찰)
- 단문/복문 비율: 단문 우세 (5회)
- 주어 생략 여부: 자주 생략 (5회)

## 어조 & 태도

- 경어 수준: 해요체/반말 혼용, 글에서는 반말(다체) (3회). **tech/\* 글에서는 중립형 "~다" 일관 사용** (2회, 반말과 호환)
- 확신 표현: **사실·행위**에는 "~했다", "~이다" 단정형 사용 (3회). **주관적 판단/의견은 "판단했다", "생각했다", "봤다" 등 1인칭 판단 표현 필수** (2회). 마지막 다짐/선언은 "~해보려 한다" 허용 (1회)
- 독자 호칭: 없음 (3회)

## 어휘 특성

- 영어 혼용: 기술 용어만 영어 원문 그대로 (LinkedIn, 스프린트 등) (2회)
- 자주 쓰는 연결어: "그런데", "하지만", "그래서"
- 즐겨 쓰는 표현: 대시(—)로 부연, 쉼표 나열로 리듬감, "~ 것 자체가 ~"로 행위에 방점

## 구조 패턴

- 도입부 방식: 스토리텔링 — 행위 묘사로 시작 (3회). **단, tech/devenv 같은 결정 중심 기술 글에서는 모티브/배경부터 — "왜 이 셋업으로 갔는가" — 가 행위 묘사보다 우선** (1회 명시 피드백, 2026-04-11)
- **Show, don't tell**: 도입부에서 시각적 결과를 텍스트로 묘사하기보다 스크린샷/다이어그램을 직접 노출. "다섯 도구가 한 화면에 모이는 layout 이다" 같은 abstract result-stating 문장은 부자연스러움 (1회 명시 피드백, 2026-04-11)
- **"결론 먼저" H2 섹션 구조 주의**: 도입과 마무리에 같은 정보 (예: 코드 박스, repo 명령) 가 중복되면 도입부에 자연스럽게 녹이고 별도 H2 는 제거. write-style.md 의 "결론 먼저" 원칙은 H2 박제가 아니라 도입부 1-2 문장 정도로 충분 (1회 명시 피드백, 2026-04-11)
- **가이드 톤 유지 — 수치 지양**: 설정값/치수 (padding 0, font size 16, history-limit 3000 등) 를 본문에 직접 인용하면 "가이드" 가 아닌 "문서/레퍼런스" 로 읽힌다. 결정의 방향만 산문으로 서술하고 구체 값은 repo 링크에 맡길 것. 긴 설정 코드 블록도 같은 이유로 압축 대상 (1회 명시 피드백, 2026-04-12)
- **"공식 기본값 → 내 커스터마이징" 2 단 구조**: 도구 섹션에서 "이 도구가 기본으로 무엇을 제공하는가" 를 먼저 한 단락으로 짚고 "그 위에 내가 무엇을 얹었는가" 를 이어붙이면 가이드 톤이 자연스럽게 나온다. 설정을 바로 인용하는 것보다 맥락이 산다 (1회 관찰, 2026-04-12)
- **공간/신체 은유 지양 (tech/\*)**: `바깥`, `얇은`, `한 겹`, `가장자리`, `틈새`, `박았다`, `묶어내는` 같은 공간/물리 은유는 tech 글에서 어색하게 읽힌다. "정말 필요한 경우" 가 아니면 직설적 표현으로 대체 — `바깥` → `터미널 에뮬레이터 / 최상위`, `얇은` → `간결한 / 가벼운`, `박았다` → `적었다 / 지정했다`, `가장자리` → `범위 밖`, `climax/hero` 같은 literary 단어도 지양. career/\* 는 literary 톤이 default 이므로 적용 제외. 영문도 동일 — `outermost`, `thin`, `baked`, `pinned`, `hero` 등 (1회 명시 피드백, 2026-04-12, 전 tech 글 재검토 후 반영)
- **의미 중첩 시 수식어 생략**: 대체어 (`간결한`, `concise`) 를 붙였는데 이미 뒷 문장 / 옆 설명이 그 의미를 담고 있으면 수식어 자체를 뺄 것. 예: "**간결한** SKILL.md + **분리된** references" → "SKILL.md 에서 **references 로 분리**" (`간결한` 을 뺌; `분리` 가 이미 `간결함` 을 함축). heading 에 `간결한` 을 붙이고 본문에 `짧고 / 한 문장` 이 있으면 heading 의 `간결한` 을 뺀다. 규칙: **남기지 말고 빼는 쪽을 default 로** (1회 명시 피드백, 2026-04-12)
- 소제목 사용: 에세이/회고에서는 거의 안 씀 (2회). **tech/\* 글에서는 적극 사용, `H2 — 한 줄 설명` 형태 허용** (2회)
- 마무리 방식: 오프닝 회수 + 여운 (5회)
- 전개 리듬: 단문 → 단문 → 대시 부연 문장 → 짧은 결론 (2회)
- **핵심 단어 볼드 강조**: tech/\* 글에서 개념 축(예: "**학습자**", "**운송 수단**")과 조건부 판단 표현(예: "**경우가 있다**")에 굵은 글씨 사용 (1회 관찰)
- **TL;DR/요약 블록 패턴**: `**키워드**. 한 문장 설명.` 형태를 3회 병렬 반복으로 핵심 요약 (tech/\* 글에서 1회 관찰)

## 선호/비선호

- 선호: 서술형 흐름 (번호 목록보다 서사적 전개), 은유적 표현, 짧은 문장으로 여백 활용, "~ 것 자체가" 식의 행위 강조, **판단은 "판단했다/생각했다/봤다"로 1인칭 명시**
- 비선호: 번호 목록으로 목표/계획 나열, "굳이" 표현 (구어체 뉘앙스가 글의 톤을 흐림), **주관적 판단을 단정형("~였다", "~이다")으로 표현 — 검증된 사실처럼 들림**, **과장된 약속형 마무리 ("이 글이 ~의 보증서다" 류) — 사실 진술 톤을 흐림** (1회 명시 피드백, 2026-04-11)
